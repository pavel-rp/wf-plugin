## Capability findings

**audit** (5 lenses dispatched against the working-tree verify-fix edit specifically, adversarially scoped to its freshly changed text: correctness, security, convention, consistency, operational — all delivered). This edit directly targeted the prior audit's residual `[FAIL]` (the id-diff marker's vacuous truth over the empty `## Growth authorizations` set) by replacing it with a self-written `- Round <N> | id-diff: complete` line the diff appends "unconditionally once the diff has run to a verdict." All five lenses confirm the *original* vacuous-empty-set defect is genuinely closed — the marker no longer reads "done" before the diff has ever run in the ordinary (no-`[growth]`-question) case. But three lenses independently found the replacement introduces a narrower, related resume gap of its own, plus two smaller residuals:

- **audit** — [FAIL] The id-diff marker can be written before its own unauthorized-growth branch is resolved, letting a resume silently skip an unresolved growth check. `SKILL.md:192` defines the marker as written "unconditionally once the diff has run to a verdict, never derived from the entries it may or may not have marked" — but the id-diff step's own third branch (`SKILL.md:193`: "any other new id → unauthorized growth — raise a user-routed check to retroactively authorize (record a fresh `consumed: yes` entry) or retire the extra id(s) back (headless: `CHARTER — Needs input`, never silently legitimized)") is not itself resolved at the moment the diff merely *categorizes* the outcome as "unauthorized growth" — resolving it requires either an interactive answer or, in headless mode, immediately halts the entire run at `CHARTER — Needs input` with nothing yet recorded. Read literally, "run to a verdict" fires on reaching that categorization, not on the categorization's resolution: nothing in `SKILL.md:192` or the new `convergence-loop.md:414-423` rationale states that the completion line is withheld until the retroactive-authorize-or-retire action actually lands — the added rationale argues only the *zero-entries* (branch-1, no `[growth]` question asked) case, and is silent on branch 3's detect-vs-resolve ordering. Consequence: a headless run that hits unauthorized growth writes `id-diff: complete` and halts; a later resume/re-invocation sees the marker present, skips the id-diff step per the same rule's "perform a step only while its marker is absent, skip it once present," and proceeds to the Phase-4 re-review carrying the still-unauthorized id forward unflagged — precisely the "never silently legitimized" outcome the same sentence forbids. Independently raised with matching file:line evidence by two lenses (correctness, operational); this task's own core adversarial pass reached the identical conclusion on the identical evidence and withdraws in their favor (see Adversarial findings below). — Remedy: state explicitly, next to the marker definition, that the id-diff completion line is written only after any unauthorized-growth check it raised has been durably resolved (a fresh `consumed: yes` entry recorded, or the extra id(s) retired) — never at the bare "verdict reached" point for that branch — or, failing that, make the unauthorized-growth check itself durable (its own `status: pending` row, mirroring the section's existing `gap: ... | status: pending` shape) so a resume can detect and re-raise it even with the id-diff marker already present.
- **audit** — [WARN] The new id-diff marker states no anchoring/forgery-resistance rule, unlike its sibling in the same sentence. `SKILL.md:192` explicitly hardens the Phase-4 re-review marker ("matched anchored at the start of a line, never as a substring, so quoted reviewer evidence can never forge it") but makes no equivalent claim for the id-diff marker introduced immediately before that clause, even though the same `## Growth authorizations` section already carries attacker/user-influenceable free text (`<gap>`/`<flag text>`, sourced through decomposer/reviewer output from charter content that can originate in tracker-supplied requirements) that nothing specifies must be escaped or newline-stripped before being interpolated into the log's bullet-line format. A short, low-entropy, guessable literal (round numbers run 1..cap, cap starts at 3) embedded in that free text could in principle produce a line indistinguishable from the marker if the resume check is a plain scan rather than a scoped match against lines the diff step itself wrote. Raised by the security lens; exploitability is unproven (depends on untrusted text surviving verbatim through the writer/decomposer rewrite and a resume landing at the right point), which is why this is `warn` rather than `fail`. — Remedy: state the same anchoring rule for the id-diff marker as for the Phase-4 heading marker, and/or strip embedded newlines/pipe-delimited-lookalike sequences from `<gap>`/`<flag text>` before they are written into any `- Round <N> | …` bullet.
- **audit** — [WARN] The new marker's row shape breaks the section's own documented fixed row grammar. `references/convergence-loop.md:446-453` (unchanged) states `## Growth authorizations` "faced the identical problem" the cap-gate section did and was solved with a labeled-field-plus-`status` grammar (`- Round <N> | gap: <flag text> | status: pending`), explicitly crediting that fixed grammar with making the section "mechanically checkable" — and the sibling `## Cap-gate decisions` section deliberately reuses rather than reinvents it. The new `- Round <N> | id-diff: complete` line instead collapses the identifying label and the completion state into a single field, and introduces a third completion vocabulary word (`complete`) alongside the existing `applied` and `consumed: yes`. Independently raised by two lenses (convention, consistency) on matching evidence. — Remedy: shape the marker as `- Round <N> | marker: id-diff | status: complete` (or reuse the section's existing `consumed:`/`applied` vocabulary) so it follows the same labeled-field-plus-`status` grammar the reference doc explicitly calls out as reused, not reinvented.
